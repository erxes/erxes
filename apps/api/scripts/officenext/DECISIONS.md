# Decisions: officenext import (core)

`pnpm --filter @erxes/api migrate:import` (`import.ts`) copies the officenext organisation's core
data from old erxes 3.4 into core's tables, keeping the Mongo ids. `steps.ts` lists every step and
the collections it reads; the last step lists every other collection with why it stays out. Each
run writes `reports/erxes-<time>.json`: seen, copied, skipped with reasons, and notes.

| Old                                                                                                      | New                                                                                                                                                | Why                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`, inactive and system members too                                                                 | `core_users`, ids and bcrypt hashes kept                                                                                                           | Members sign in with their old password; a member whose email another member has merges into that member through the id map                    |
| User groups and their grants                                                                             | One role per group, with the core actions its grants cover                                                                                         | Core gives each member one role; grants to single members and plugin actions have no core action                                               |
| `branches`, `departments`, `units`, `structures`                                                         | `core_org_units` (Branch, Department, Team, Company); deleted units left out                                                                       | A missing or wrong-kind parent puts the unit at the top; a taken code gets a suffix                                                            |
| `tags` of core record types; untyped tags                                                                | `core_tags`; untyped ones as customer tags                                                                                                         | Plugin tag types are the plugins' own; a name taken for the type merges through the id map                                                     |
| Tag parents                                                                                              | Dropped                                                                                                                                            | Core tags are flat (erxes/erxes#10843)                                                                                                         |
| `brands`                                                                                                 | Tags `Brand: <name>` of each type                                                                                                                  | Records keep their `scopeBrandIds` as tags; core has no brands or tag groups (erxes/erxes#10842)                                               |
| A primary email or phone another customer has                                                            | Kept in the customer's list, not as primary                                                                                                        | Core keeps one customer per primary email and phone                                                                                            |
| A company name already used, or none                                                                     | Name plus its code or id end; else its other name, email, website or id                                                                            | Company names are unique                                                                                                                       |
| Company parent                                                                                           | Kept in `source_details`                                                                                                                           | No column (erxes/erxes#10844)                                                                                                                  |
| Merged customers and companies (`deleted` + `mergedIds`)                                                 | Id map rows to the record kept, not rows                                                                                                           | Plugins and links find the record kept                                                                                                         |
| Customer ↔ company `conformities` and `relations`                                                        | `core_customer_companies`                                                                                                                          | Other pairs (deals, tasks, tickets, conversations) are counted as `plugin:<name>`; old erxes stored many pairs more than once                  |
| `client_portal_users`                                                                                    | The customer they point at (else by email, phone, or a new one); verified addresses become `core_customer_logins`                                  | Core signs customers in with codes, so passwords, tokens and devices stay out                                                                  |
| `products`, `product_categories`, `uoms`                                                                 | Core products; deleted ones archived; prices ×100                                                                                                  | Old deals still find their products; a taken code or barcode gets a suffix                                                                     |
| Field groups and fields of every record type, plugin ones too                                            | `core_field_groups`, `core_fields`, ids kept; plugin types use the plugin's record type (`operation.task`)                                         | Plugin importers find fields by old id; `plugin` stays null; every field gets an id map row                                                    |
| Form fields (no content type)                                                                            | Left out, `plugin:frontline`                                                                                                                       | Forms are Frontline's                                                                                                                          |
| Member fields (`core:user`) and their values                                                             | Left out                                                                                                                                           | Core fields have no member record type (erxes/erxes#10845)                                                                                     |
| `customFieldsData`, `propertiesData`, `trackedData`                                                      | `core_*_field_values`; tracked data as text fields in a "Tracked data" group                                                                       | The typed copy wins; options stored by label                                                                                                   |
| `internal_notes` on customers, companies, deals, tasks, tickets, conversations                           | `core_activities` (`<type>.note`) and `core_notes`; HTML as text; mentions kept                                                                    | Notes on records deleted in old erxes are skipped; product notes have no timeline (erxes/erxes#10848)                                          |
| `activity_logs` about a record                                                                           | `core_activities`, source `erxes3`, with the sentence old erxes showed; "created" ones as core's own `customer.created`                            | The record's timeline; `dedupe_key` keeps a re-run from adding it twice                                                                        |
| `activity_logs` with no record (sign-ins, permission changes)                                            | `core_audit_logs`                                                                                                                                  | Not a timeline entry; every row kept                                                                                                           |
| `operation_notes`, `frontline_tickets_notes` with `isInternal`                                           | Notes on the task, project or ticket, as `internal_notes` are                                                                                      | Operation's and Frontline's importers leave them to core; a ticket's comments to the customer stay with Frontline                              |
| `operation_activities`, `frontline_ticket_activities`                                                    | `core_activities`, source `erxes3`, typed `<type>.<module>_<action>` ("Changed status"), old and new value in `data`                               | Operation's and Frontline's importers leave them to core; "created note" entries are left out, since the note itself comes in                  |
| `logs`, `erxes_logs.logs` (5.7M change events)                                                           | `core_audit_logs`, source `erxes3`, oldest first; passwords, tokens and keys in the data `[redacted]`                                              | They are audit history; core's prune job deletes rows past `AUDIT_RETENTION_DAYS`, so raise it before the import (erxes/erxes#10841)           |
| `notifications`                                                                                          | `core_notifications` for members in core; read, or past their expiry, ones come in read                                                            | Members aren't handed thousands of stale unread ones                                                                                           |
| Named customer, lead, company and product `segments` with plain rules                                    | Shared `core_views`; custom fields as `subject.customFields.<id>`                                                                                  | Rules on relative dates, events or fields core lacks keep the segment out; unnamed segments were parts of others                               |
| Email campaigns (`broadcast_engage_messages`, `engage_messages`, `erxes_office_engages.engage_messages`) | `core_broadcasts`: `sent` at their last run, else `cancelled`; HTML body as text                                                                   | History only: nothing can send to an audience core can't rebuild; auto campaigns keep their last run                                           |
| `broadcast_recipients`, delivery reports                                                                 | `core_broadcast_recipients`, one per campaign and customer, at the customer's core email                                                           | Reports have no times, so sent, opened and clicked take the campaign's last run                                                                |
| Messenger and app-notice campaigns                                                                       | Left out                                                                                                                                           | `plugin:frontline`; core has no app-notice channel                                                                                             |
| `email_addresses` old erxes stopped mailing                                                              | `core_suppressions`, reason `manual`, the screening reason as detail                                                                               | Its screening (syntax, no mail server, random) was the only reason                                                                             |
| `favorites`                                                                                              | `core_favorites` when the page is a core page that kept its address                                                                                | Old plugin pages have other addresses in the new plugins                                                                                       |
| `files`, `filemanager_files`                                                                             | `core_files`, keeping the storage key or URL as the key                                                                                            | Core files have no folders or shares (erxes/erxes#10846); `file_versions` held one version each                                                |
| `automations` and their runs and notes                                                                   | Left out                                                                                                                                           | Every one uses a plugin trigger or action (Facebook, inbox, Sales, POS, AI agent) or is archived or a template                                 |
| `payment_methods` (the list old erxes used)                                                              | `core_payment_gateways`, settings renamed to core's and sealed with the API server's key (`CORE_ENCRYPTION_KEY_FILE`); old state kept              | QPay quick QR has no core gateway (erxes/erxes#10853); the Stripe publishable key is dropped, core needs only the secret one                   |
| `payments` (the older plugin's list)                                                                     | `core_payment_gateways`, turned off                                                                                                                | `payment_methods` replaced it; its gateways come in for their old invoices; a Pocket without terminal id and a half-set Storepay stay out      |
| `golomt_bank_configs`, `payment_configs`                                                                 | Left out                                                                                                                                           | A Golomt bank-statement API, not a card gateway; which gateways a messenger offered is Frontline's                                             |
| `payment_invoices`, `invoices`, `payment_transactions`                                                   | `core_payment_invoices`, amounts ×100; a paid one takes its transaction's gateway, amount and time; pending ones come in `expired`                 | The gateway it was paid through, else the first core has; with none (quick QR), `transfer`; no tax receipt asked; core has no refunds to carry |
| `put_responses` (deal eBarimt receipts)                                                                  | One recorded invoice per deal (`ebarimt-<deal>`: paid, cash or transfer, the receipt's lines), and every receipt on it                             | A core receipt needs an invoice and the old ones had none; the returned ones keep `inactive_at`, refused tries are `failed`                    |
| `webhooks`                                                                                               | `core_webhooks`, turned off, the old token as the sealed signing secret; old actions as core event types                                           | Core signs deliveries and old endpoints checked the token, so a member turns each on once its endpoint checks core's signature                 |
| `ebarimt_product_rules`, `vat_rows`, `ctax_rows`                                                         | Left out                                                                                                                                           | Core eBarimt settings need the merchant registration, which members enter again                                                                |
| `configs`                                                                                                | Left out                                                                                                                                           | Credentials and service settings; the currency is already MNT; core has no time zone setting (erxes/erxes#10847)                               |
| `email_templates`                                                                                        | Left out                                                                                                                                           | Core has no template library (erxes/erxes#10652); broadcasts keep their own body                                                               |
| v1 copy `erxes_office`                                                                                   | Its customers, companies, notes, conformities, fields and logs whose `_id` `erxes` lacks, through the same mappers; the overlap counted as skipped | 20,141 of the 20,934 v1-only customers are 2020 leads `erxes` no longer has; they come back as leads                                           |
