| 12  | One product catalog per organisation, in core, shared by every plugin (Ecom, TMS, PMS, Sales …), so one org running several plugins has one list of products, not one per plugin. Core keeps what every seller needs: kind (goods or service), name, code, barcode, category, price, unit, images, size and weight. Each product lists the plugins that use it (`plugins`); a plugin lists its own by default, searches all with `all`, and joins or leaves a product with `products.use`. Members choose the plugins on the product. Products are archived, never deleted, so old orders and invoices still resolve. Plugin-only data (stock, variants, room rates) stays in the plugin's tables, keyed by the product id. What the organisation itself wants on every product (brand, warranty) is a product property (custom field), which every plugin reads. A taken code or barcode answers with the existing product's id, so a plugin syncing its own catalog links instead of copying.
