# @erxes/core-contract

The `/core/v1` API contract (zod 4 + `@orpc/contract`) and event schemas. Core implements it,
core-ui and plugins call it with a typed client, and `openapi.json` describes it for everyone else.

Types flow one way: the Drizzle table (`@erxes/core-db/schema`) → drizzle-zod → these schemas →
the oRPC router and `openapi.json` → `@orpc/tanstack-query` in core-ui. Renaming a column fails
the type check in the contract, the services and core-ui.

Clients take only the types from that chain. At runtime they pass `coreRoutes`
(`@erxes/core-contract/routes`, the generated `routes.json`) to `OpenAPILink` and import values
from `src/values.ts`, so a browser never loads a table or drizzle. The core-ui build fails if it does.

## Layout

- `src/<domain>.ts` has the domain's schemas and its `<domain>Contract` of procedures.
- `src/index.ts` assembles `coreContract`.
- `src/values.ts` has what browsers use at runtime and builds on no table: `CORE_API_PREFIX`
  (`/core/v1`), the z.enums a UI lists (`ProductKind`, `InvoiceStatus`, `FieldType`, …), `RoleKey`,
  `NewPassword`, `PAYMENT_GATEWAYS`, `CORE_NOTIFICATION_GROUPS`. A value a UI imports goes here,
  or in another module with no table import (`common.ts`, `money.ts`, `automationDefinition.ts`).
- `src/routes.ts` exports `coreRoutes` from `routes.json`: each procedure's method and path, no schemas.
- `src/common.ts` has shared pieces: `Id`, `IdList`, `CursorQuery`, `cursorPageOf`, `isoDate`.
- `src/leads.ts` has the lifecycle columns customers and companies share: `LIFECYCLE_COLUMNS`,
  `lifecycleRow`, `lifecycleInput`, `LIFECYCLE_INPUT_COLUMNS`.
- `src/events.ts` has the event schemas plugins publish (`EventInput`, `EventNotify`).
- `src/live.ts` has the `/core/v1/stream` messages (`LiveHello`, `LiveTimeline`). The stream is
  Server-Sent Events outside the oRPC router, so it is not in `openapi.json`.
- `openapi.json` and `routes.json` are generated by `pnpm openapi` (`apps/core-api/scripts/openapi.ts`)
  from `generateOpenApi()` and `minifyContractRouter(coreContract)`. Never edit them by hand.

## Rules

- A procedure is `oc.route({ method, path, successStatus?, summary })`, `.input()` and `.output()`.
  Paths are relative to `/core/v1`. Input is one object: path params, query and body merged
  (`{ id, ...changes }`). The summary names the error codes the procedure adds (`409 TAG_EXISTS`).
- Ids are text (`Id`). List queries extend `CursorQuery` and answer `cursorPageOf(Row)`.
- Outputs never include credentials or `org_id`.
- Types come from these schemas (`z.infer`). Nothing downstream hand-writes an API shape.
- A schema that mirrors a table starts from the table. Copy `src/tags.ts`:
  - Output: `createSelectSchema(table, refinements).pick({ ... })`, then `.extend({ ... })` for
    computed fields (`tagIds`, `editable`, `actor`). Pick every column by name; never `.omit()` from a table schema,
    so a new column (a hash, a secret, `orgId`) stays private until someone picks it.
  - Input: `createUpdateSchema(table, rules).pick({ ... })` gives every field optional. Create
    is `.required({ name: true })`, update is `.extend({ id: Id })`. Not `createInsertSchema`
    with refinements: drizzle-zod 0.8.3 types a refined optional column as required.
  - Refinements keep the API's rules: `(name) => name.trim().min(1).max(100)` keeps the column's
    nullability (a nullable column becomes `.nullable()`, and `.optional()` in update schemas).
    A schema value (`Id`, `z.iso.datetime()`) replaces the column as it is: add `.nullable()` or
    `.optional()` yourself.
  - Override what drizzle-zod infers differently: `id: Id`, timestamps `isoDate`, integers
    `() => z.int()` (it adds the column's int32 or int53 bounds), jsonb columns their real shape.
  - Enums come from the arrays in `@erxes/core-db/enums`, the same ones the columns use:
    `z.enum(CONTENT_TYPES)`, not a second list.
- Check `openapi.json` after every change: zero difference unless the API is meant to change.
  Property order may move (computed fields come last); that is not a change.
- The contract imports only `@erxes/core-db/schema` and `@erxes/core-db/enums` from the database
  package: table definitions and value lists, no client or driver. The published build copies them
  into dist, so they never import Node, `pg` or `../client` (`no-restricted-imports`, `noDriver` in
  `tools/lint/restricted-imports.ts`).
- The package has no import-time side effects and imports no app (`no-restricted-imports`).

## Versioning

The package is a `0.1.0-v2.N` prerelease on npm's `v2-next` dist-tag. This policy starts with `1.0.0`.

- Semver on the published contract (and the SDK built from it).
- Additive changes are a minor version: a new procedure, a new optional input field, a new output
  field, a new error code.
- Breaking changes are a major version: removing or renaming a procedure, path or field, making an
  input field required or stricter, changing a field's type or meaning, reusing an error code.
- A breaking change ships next to the old shape for a deprecation window: mark the old procedure
  or field deprecated in the summary and keep it for at least one minor release before the major.
  On the HTTP side a breaking change goes under `/core/v2`.
- Future (Phase 2): CI diffs `openapi.json` against the base branch and flags breaking changes.

## Check

`pnpm check:generated` (fails when `openapi.json` or `routes.json` is stale), `pnpm check`, and the API tests.
